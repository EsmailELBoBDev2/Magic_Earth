# CairoDrive v24 Google Free Drive traffic audit

## Free Drive traffic
- Source: Google Map Tiles API session with `layerTraffic`, `overlay=true`, 1x PNG.
- Scope: only nearby tiles around the current vehicle position.
- Moving: 6 forward-biased tiles. Slow/stationary: 3x3 = 9 tiles.
- Zoom: z16 for normal Cairo driving; z15 at >=22 m/s to cover farther highway distance with fewer tile changes.
- Raster work: one Java worker, `Bitmap.getPixels()` once per refreshed tile, coarse traffic grid, no per-frame work.
- Waze-style sparsity: green/free-flow is discarded; only SLOW/JAM survives.
- Rendering: max 36 geographic Magic Lane `Path` objects. No Android Canvas/GL overlay and no frame hook.
- API economy: session token reused, tile Cache-Control respected, ETag revalidation, window-change + 75s moving / 120s slow refresh gates.

## Audit fixes bundled
- Correct exact-APK Magic Lane coordinate wrapper package: `com.magiclane.sdk.places.Coordinates`/`CoordinatesList`.
- Active-navigation traffic rendering resampled from the native Magic Lane route every 12m, then simplified.
- Remove Google retry on valid empty/parse result; retry only network failures.
- Preserve completed AsyncHttp states until polled instead of reaping immediately.
- Bound stale per-thread category contexts.
- Dispose retained navigation wrappers when sessions are replaced/end.
- Do not force Magic Earth's stock traffic preference on.
- Remove dead custom UI/logging classes, obsolete one-shot hardening workflow/transform, old route experiments, obsolete debounce tool, and checked-in drive-test keystore material.

## Important Google policy note
Google's current Map Tiles policy explicitly prohibits image analysis/machine interpretation/geodata extraction. This raster-to-vector path is therefore experimental and is not a compliant production/distribution architecture under those terms. The implementation also uses a separate runtime Map Tiles key so it can be disabled independently.
