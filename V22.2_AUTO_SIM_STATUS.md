# CairoDrive v22.3 — route algorithm + simulation status

## Is anything exact-target-safe still waiting to be added?

**No.** The exact original `7.1.26.26` APK was inspected directly before this freeze.

Its Android routing surface contains:

- `ERoutePathAlgorithm.MagicEarth`
- `ERoutePathAlgorithm.ExternalCh`
- `startNavigation`
- `startNavigationWithRoute`
- `startSimulation`
- `startSimulationWithRoute`
- `isSimulationActive`

The exact APK does **not** expose the newer `simplifiedMl` / `mlch` enum names. They are therefore not “waiting for testing”; they are deliberately excluded as incompatible/unproven for this target.

## What v22.3 now does

Normal app operation is still real Magic Lane navigation and defaults safely to stock `MagicEarth`.

Test mode is explicit and no-drive:

```text
/data/local/tmp/cairodrive_simulation = benchmark
```

When armed, CairoDrive converts stock `startNavigation*` requests to a compatible native `startSimulation*` overload. If it cannot find a compatible overload it **blocks the test start instead of falling through to real navigation**.

The automatic A/B runner tests:

1. `stock`
2. `externalch-reroute`
3. `externalch-all`

using fixed short/mid/long Cairo cases. It injects a bounded native Magic Lane roadblock while simulation is active and measures the real route update via `ROUTE_RECOMPUTE_E2E`.

The winner gate checks:

- actual pathAlgorithm application (not just requested mode)
- successful simulation/recompute
- p50/p90/mean/% under 1 second
- fatal/ANR/native-crash markers
- paired route distance + ETA
- known narrow-route regression when metadata exists

A candidate must produce a meaningful safe win. Small or inconclusive differences fail safe to `stock`.

At the end the script writes the selected production mode to:

```text
/data/local/tmp/cairodrive_route_algo
```

and removes every simulation/benchmark marker before relaunching CairoDrive normally.

## Important performance/safety detail

Traffic-only reroutes disable terrain-profile construction for speed. A reroute specifically escaping strong `SingleTrack` / `Path` evidence retains terrain metadata so CairoDrive can still check the replacement for another narrow-road trap. This prevents the `<1 s` optimization from silently weakening the narrow-road objective.

## What still requires a phone

Only the **empirical winner**. The proprietary Magic Lane ARM64 routing engine cannot be truthfully benchmarked in this desktop/container environment. v22.3 turns that remaining measurement into a one-command exact-device test rather than a manual development loop.
